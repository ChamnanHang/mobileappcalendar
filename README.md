# Noted

A modern, offline-first notes app built with Flutter — dark glassmorphic UI, neon accents, and a
live markdown editor.

## Features

- **Notes & checklists** — two note types; checklists show a progress bar and tickable items you can
  toggle straight from the home grid.
- **Live markdown editor** — `**bold**`, `*italic*`, `` `code` ``, `~~strike~~`, `#` headings,
  `- ` bullets, `- [ ] ` tasks and `> ` quotes style themselves *as you type*, with a formatting
  toolbar above the keyboard.
- **Folders & tags** — one folder per note plus free-form tags; filter by either from the home screen.
- **Pin, favourite, archive** — pinned notes float to the top, favourites get their own view, and
  archiving is a sideways swipe with undo.
- **Search** — matches titles, body text, tags and checklist items.
- **Khmer lunar calendar** — a month grid showing each day's lunar date (កើត / រោច), Buddhist holy
  days, Khmer New Year, and which days already have notes. Swipe sideways to change month. Computed
  on-device. See below.
- **Fully offline** — notes are stored on the device and the calendar is computed locally. No
  account, no server, no network calls at all.
- **Accessible** — every control has a screen-reader label and a 44–48dp touch target, calendar
  cells announce their full date and lunar day, and the app honours the platform's reduce-motion
  setting.

## Design

Dark aurora background (animated neon blobs painted on a canvas), frosted-glass panels, six
selectable per-note accent colours, and spring-loaded micro-interactions. The type scale uses the
platform system face (SF Pro / Roboto), so nothing is fetched at runtime.

The app is dark-only: `themeMode` is pinned, and both launch screens use `AppColors.bg` so there is
no white flash on a light-mode device.

### Where the frames go

A few deliberate choices, because this is the kind of UI that gets slow quietly:

- **Blur is rationed.** `BackdropFilter` costs a `saveLayer` plus a gaussian pass over the pixels
  behind it, per panel, per frame. The chrome that sits over scrolling content — nav bar, sheets,
  search field, toolbar — pays it. Note cards do not (`GlassPanel(blurred: false)`): dozens are on
  screen at once, and what is behind them is the aurora, an already-smooth gradient, so blurring it
  returns very nearly the same pixels.
- **The grid is lazy.** Notes are chunked into a `SliverList` rather than built all at once, so
  build cost tracks the viewport, not the library size. Each card is a `RepaintBoundary`.
- **Derived state is computed once per change, not once per build.** `visibleNotes`, `allTags`,
  `allFolders` and the counts are cached on `NotesController` and invalidated on mutation; a note's
  stripped-markdown preview and its folded-case search index are cached on the immutable `Note`.
- **Typing does not rebuild the editor.** A `TextField` already owns its text, so title, body and
  checklist edits update the model without `setState`; structural edits still rebuild.
- **The calendar caches months.** `KhmerMonthCache` is a small LRU, with the neighbouring months
  warmed in a microtask so an arrow tap or a swipe lands on a grid that already exists.
- **The aurora stops when asked.** It respects reduce-motion, and instances share a phase so the
  background does not jump when the editor fades in over the list.

## Khmer calendar

Computed **on-device** — no network, no API. [lib/data/khmer_lunar.dart](lib/data/khmer_lunar.dart)
is a pure-Dart port of the momentkh / Soriyatra Lerng Sak algorithm, ported from the Python
reference in `~/Desktop/Coding/khmer_calendar` (the same code deployed behind
khmer-calendar-phi.vercel.app).

The month header shows the Khmer month and Buddhist Era year, each cell shows its lunar day, holy
days are marked, and the selected day gets the full Khmer sentence. A whole 42-cell month grid
computes in a few milliseconds, so there is no loading state anywhere.

### Verified against the reference

`test/khmer_lunar_test.dart` diffs the Dart port against `test/fixtures/khmer_reference.json`,
generated by running the Python implementation:

| Checked | Cases |
| --- | --- |
| lunar day + month | 5,706 dates (every day 2024–2030, plus a sweep of 1900–2150) |
| formatted sentence + BE year | 133 dates |
| Buddhist holy day | 181 consecutive days |
| Khmer New Year days | 138 years |

### Holidays and events

[lib/data/khmer_holidays.dart](lib/data/khmer_holidays.dart) derives Cambodian holidays from lunar
rules rather than a per-year table, so they are correct for any year. Verified against Cambodia's
**Sub-Decree No. 167 (18 September 2025)** — the official 2026 schedule — in both directions: every
official date is flagged, and nothing else claims to be a public holiday.

| Event | Rule (lunar day index is 0-based) |
| --- | --- |
| ភ្ជុំបិណ្ឌ Pchum Ben | ខែភទ្របទ idx 29; the holiday is main −1, main, main +1 |
| កាន់បិណ្ឌ Kan Ben | ខែភទ្របទ idx 15–28 (observance) |
| វិសាខបូជា Visakha Bochea | ខែពិសាខ idx 14 |
| ច្រត់ព្រះនង្គ័ល Royal Ploughing | ខែពិសាខ idx 18 |
| មាឃបូជា Meak Bochea | ខែមាឃ idx 14 (observance) |
| ចូលវស្សា / ចេញវស្សា | ខែអាសាឍ or ទុតិយាសាឍ idx 15 / ខែអស្សុជ idx 14 (observances) |
| អុំទូក Water Festival | ខែកក្ដិក idx 13–15 |
| បុណ្យចូលឆ្នាំថ្មី Khmer New Year | from the Soriyatra solar computation |

Fixed-date holidays (including Peace Day, added by sub-decree in 2024) are in the same file. The
list is re-issued annually, so check a specific year's decree if it matters legally.

> ⚠️ **Do not validate against the old web API.** It answers 13 April 2026 for Khmer New Year, while
> the sub-decree, published calendars and this port all say 14–16 April. The Python repo's HEAD
> commit is "fix Khmer New Year calculation for years where lunar epoch crosses month boundary" —
> the Vercel deployment predates that fix.

### Differences from the Python reference

Two deliberate ones:

- **Holy days.** The rule is the 8th and 15th of either fortnight, *plus* the 14th waning when the
  next day is the 1st waxing (a short month). Both implementations agree.
- **Hour 24.** The Python builds the New Year date with `strptime`, which rejects an hour of `24`,
  so the deployed service returns **500** for 1974, 2032 and 2059. Here hour 24 rolls into the next
  day, which is the correct reading — covered by a test.

Khmer glyphs rely on the platform font: Android and iOS carry Khmer system fonts, while Flutter web
fetches a Noto fallback at runtime, so the first paint on web can briefly show ▯▯▯ boxes. Bundling
`NotoSansKhmer` as an asset would remove that dependency.

## Running it

```bash
flutter run -d chrome
```

Web is the only target that runs on this machine as-is. For phones you'll need the platform SDKs:

- **iOS** — install Xcode from the App Store, then `sudo xcode-select -s /Applications/Xcode.app`
  and `flutter run -d ios`. (Only Command Line Tools are installed right now.)
- **Android** — install Android Studio plus an SDK and emulator image, then `flutter run -d android`.

Run `flutter doctor` to confirm what's missing.

## Tests

```bash
flutter test
```

98 tests cover the notes controller (sorting, filtering, search, archive, undo, cache invalidation,
save durability), JSON persistence round-trips, the markdown helpers, the `Note` derived-state
caches, the Khmer lunar algorithm (see the table above), the month cache and its LRU eviction, and
widget tests for boot / open / search / calendar / month swipe / the expanding FAB / reduce-motion.

> The aurora background animates continuously, so widget tests advance frames with
> `tester.pump(duration)` — `pumpAndSettle` would never return. The one exception is the
> reduce-motion test, which asserts exactly that: with animations disabled the tree settles.

## Storage note

Notes persist as a single JSON blob through `shared_preferences`, chosen because it works
identically on mobile **and** web. Persistence sits behind the `NoteStore` interface, so swapping in
SQLite (`sqflite`), Isar, or a sync backend means writing one class — no UI changes.

Writes are debounced by 350ms to coalesce bursts of edits. Because both mobile platforms can kill a
backgrounded process without further warning, an `AppLifecycleListener` flushes anything still
pending on inactive/pause/hide/detach, and `dispose` writes rather than cancelling — otherwise an
edit made in the last third of a second before backgrounding would simply be gone.
